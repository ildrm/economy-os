Review date: 2026-09-05. This maps the **40 numbered criteria in section 125** of the user's assignment to inspected implementation evidence. It is a product acceptance review, not a declaration that the complete assignment or any roadmap phase is accepted.

`Implemented, scoped` means executable behavior exists for the named narrow scope. `Partial` means a material portion of the criterion remains absent or unverified. `Not implemented` refers to the requested new capability, not deletion or absence of the platform's existing generic engines. Tests being present is distinguished from recorded execution; the root audit report owns final full-suite counts and external-service results.

## Research workflow and failure-mode review

The implemented user path is: choose an intertemporal or material-balance calculation, supply workspace/cutoff and assumptions or quantities, execute through the authorized API, inspect a hypothetical result, and expand its immutable input/provenance envelope. Fields start empty; omitted material quantities remain unknown. Editing a field invalidates the prior displayed result, and late responses are rejected after context changes. Exact retry identity is retained for unchanged inputs. These behaviors are covered by browser tests with explicitly synthetic routed responses; such tests do **not** demonstrate a live authenticated browser-to-database session.

The current UI is not a substitute for the requested end-to-end chain from a measured economic state through source disagreement, identified drivers, reviewed causal interpretation and a governed scenario. In particular, evidence review queues, historical plan exploration, causal validation and deployment approval cannot be exercised through the new forms. A user-entered utility stream is a scenario assumption; a lexical intervention match is a candidate; a graph hypothesis is not an estimated causal effect; a stored run is not admitted observation data.

## Architecture and reproducibility review

The allocation package has no runtime workspace dependencies and imports only Node cryptographic hashing outside its own domain files. It contains no HTTP/SQL/UI/provider imports, clock reads, random draws, global tenant sessions or hidden objective function. Arithmetic uses exact bigint rationals and canonical decimal strings. Canonical serialization sorts object keys, while explicit array ordering remains part of the input identity. Immutable scenario outputs include the input manifest, baseline digest, assumptions, model version and unquantified model uncertainty. Repeatability is a computational property, not empirical validity.

Behavioral integration delegates graph and feature construction to their existing packages. This is preferable to reimplementing those contracts in a controller. Its chronology/validation gates support a bounded research bridge; they do not independently certify caller-provided held-out scores, create real data, or transport an estimate to a new population. The new behavioral package depends on contracts, narrative-intelligence, forecasting-engine and causal-graph; these inspected packages do not import behavioral-economics back, so this addition introduces no workspace cycle.

The scientific cross-review identified risks in silently retaining one measurement per definition, mismatching graph-node IDs with hypothesis subject IDs, and allowing a hypothesis population to differ from its evidence population. Owners received those findings for correction and regression tests. The owner added source-retention, node-identity and population checks in response. Regression outcomes and any remaining performance follow-up are recorded in the root report; source changes alone are not evidence of a completed empirical workflow.

The root database verification subsequently passed all 40 migrations and its two-tenant RLS, append-only, PIT, ingestion, lifecycle, collaboration and behavioral/allocation SQL suites. The newly completed lifecycle script is included in `database/verify.ts`. This verifies the registrar defaults and security regressions on the explicitly disposable development database; it is not a production deployment.
